# AI Native 开发模式

## 核心理念

AI Native 开发不是让 AI 直接替代所有决策，而是让 AI 成为“可读规范、可追溯需求、可验证结果”的执行者。

## 协作闭环

```text
人类提出目标
  ↓
AI 澄清需求并生成 Plan
  ↓
人类确认边界和风险
  ↓
AI 小步实现
  ↓
AI 执行测试与自检
  ↓
人类验收或要求修正
```

## 角色分工

| 角色 | 主要职责 |
| --- | --- |
| 人类负责人 | 业务目标、优先级、验收、风险审批 |
| 规划 Agent | 澄清需求、拆解任务、维护 Plan 与登记册 |
| 开发 Agent | 读取规范、实现代码、同步模块文档 |
| 测试 Agent | 设计测试、执行验证、输出风险 |
| 审查 Agent | 依据规范检查缺陷、回归风险和遗漏测试 |

## 必须人工确认的事项

高风险动作（数据删除/迁移、生产配置、认证授权/密钥、部署上线/回滚等）**必须人工确认**。完整清单以单一权威来源为准：见 `../standards/agent-workflow.md` §8「自动推进与人工确认」，此处不重复维护。

## 文档即上下文

AI 执行前应优先读取项目文档，而不是依赖历史对话：

- `docs/standards/`：长期规则。
- `docs/requirements/`：当前需求和验收标准。
- `docs/modules/`：模块边界、设计、API、测试。
- `docs/deploy/`：环境和发布约束。
- `docs/reports/code-review/`：历史审查结论。

## 质量原则

- 需求必须可追溯到登记册。
- 设计必须说明取舍和风险。
- 实现必须遵守编码规范。
- 测试必须覆盖验收标准。
- 未完成或未验证事项必须显式记录。
