# 前端导航规范

菜单分组、布局与页面标题的规范，同时遵循 [前端界面规范](./frontend-ui.md)；路由守卫与地址栏见 [前端路由规范](./frontend-routing.md)。

导航与项目长过渡共用一个等待进度条，统一等待 300ms 才显示，页面仍保留首屏骨架。布局在顶栏与内容之间放 `<app-navigation-progress placement="content" />`，进度条出现在内容区顶部；没有布局的页面（登录、404 等）由根组件在视口顶部显示。新增布局照此挂载。项目过渡调用 `NavigationProgressService.begin()`，在成功、失败或取消的收尾中调用返回的释放函数；多个占用全部结束才隐藏，重复释放无副作用。
<!--#if (IncludeRealTime)-->

实时连接异常提示条 `<app-realtime-status />` 紧跟进度条挂载：顶栏 → 进度条（零高度叠放）→ 提示条（占布局流，不盖住页面）→ 滚动区；工作空间布局里随内容限宽到 `max-w-7xl`。连接正常时不占位，新增布局照此挂载。

## 1. 导航与菜单分组

导航菜单是**信息架构**，不是控件清单：分组摆错了既不报错也不影响功能，只是让人找不到入口。两个区各有一套菜单，都定义在 `frontend/src/app/layout/services/navigation-service.ts` 一处，管理平台的侧栏与工作空间的顶栏都从这里读，判据相同。

| 分组 | 放什么 | 现有入口 |
| --- | --- | --- |
| 工作 | 进来先看的东西：本区落地页、待办、我的任务 | 平台「仪表盘」/ 工作空间「工作台」 |
| 业务 | 这个系统"做业务"的地方 | 模板只放一个「示例模块」占位，下游项目在这里加自己的 |
| 身份与访问 | 谁能用、能用什么 | 用户管理、角色管理、租户管理 |
| 集成 | 本系统与外部系统、服务之间的连接：第三方接进来、向外推送、服务间消息 | 开放应用（OAuth 客户端）、Webhook、分布式事件 |
| 审计 | 谁在什么时候做了什么 | 操作记录（登录记录、导出记录同属这一类） |
| 系统 | 本租户（或宿主）的默认值与策略 | 系统设置（注册、登录与会话、邮件发送、运维、数据保留等面板，一个后端设置分组一个面板） |

- **不设「其它」这类兜底组。** 新入口必须落进上表某一类；落不进就新开一类并把判据补进表里。
- **按用户的目的分组，不按后端模块或表结构分组。** 用户找的是"我要做什么"，不是"这属于哪个服务"。
- **管理平台的菜单分组与后端的权限分组同名同序。** 每个菜单项只挂它对应的根权限，菜单项标题与根权限显示名一致，英文一律句首大写（sentence case，专有名词与缩写照写），这是与后端共同遵守的命名约定，见 [后端开发规范](./coding-backend.md#39-权限)。菜单项的权限必须列进 `PLATFORM_ENTRY_PERMISSIONS`，由 `default-sidebar.spec.ts` 核对。
- **个人设置只有一处：头像菜单里的「个人设置」**（工作空间的 `/workspace/settings`），管理人员从管理平台进的也是同一处；菜单树与管理平台都不另放入口。系统设置放管理平台「系统」组，作用域不同，不合并。
- 监控、健康检查、后台任务这类"系统怎么跑"的东西以后若要进导航，新开「运维」组；日志级别这类运维**配置**放在系统设置的「运维」面板里，不进导航。
- **头像菜单里不放「切换租户」。** 会话租户在登录时定案，换租户只能退出后在登录页重选。
- 菜单项只按权限裁剪（`permissions` 任一命中即可见），整组为空时**整组消失**，不留空标题——空标题看起来像加载失败。
- 命令面板（⌘K / Ctrl+K，侧栏与顶栏的搜索入口）列的是当前区按权限裁剪后的同一份菜单加另一区入口，不另建命令清单；新增菜单项自动出现在面板里。
- **按"能不能做"分支，不按"我是谁"分支。** 区分宿主侧与租户侧看权限：服务端下发的权限已按侧别过滤。不要从 `TenantContextService` 推导侧别——本地身份形态下它只是登录页的路由提示，可能与会话租户不一致。权限表达不了的显示决定由页面所属的业务端点连同数据下发结论。
- 侧栏分组骨架由 `default-sidebar.spec.ts`、头像菜单构成由 `user-menu.spec.ts`（按完整序列断言）钉住，改导航同时改用例。

## 2. 布局与页面标题

- **页面标题设 `LayoutService.title`**（面包屑末级）：每个布局页在构造函数或 `effect` 里设一次，本地化形态用 `translateSignal`，语言切换随之更新。页头按它输出视觉隐藏的 `h1`（未设不输出），布局内页面的标题因此从 `h2` 起、逐级不跳；登录、注册、错误页等不在这两种布局里的页面自带 `h1`。浏览器标签页标题由根组件统一合成为「页面标题 · 应用名」（`Title` 服务），页面不要自己调 `Title`；页头随布局销毁时清空页面标题，登录页、落地页等不设标题的页因此只显示应用名。应用名是 `frontend/src/app/app.ts` 的 `APP_NAME`，本地化形态取词条 `app.name`、缺词条时回落到它；改项目名时两处连同 `frontend/src/index.html` 的 `<title>` 一起改。
- **嵌套页的层级由面包屑承担**：列表下的详情、工作台的子页与标题一起设 `LayoutService.trail`（首页与当前页之间的上级，文案 + 绝对链接，离首页近的在前），用 `DestroyRef` 在离开时清空；一级页面不设。面包屑由 `app-page-breadcrumb` 渲染为「首页 > 上级… > 当前页」：上级两级及以上时只留最近一级，更远的收进省略号下拉（Spartan breadcrumb 的折叠用法）；窄屏只留最近一级上级作为返回入口。侧栏布局放在页头，顶栏布局在设了上级时放在正文上方。页面内不另放「返回…」链接（空态里的去处按钮除外），返回目标因此不会与面包屑不符。
- **页头按自身宽度给面包屑留位**：页头内容层是尺寸容器 `@container/header`，右侧控件用 `@…/header:` 变体按页头宽度切换，不按视口——侧栏展开时页头比视口窄。区段、租户、工作区一类上下文选择器有两种放法：放在侧栏头部（`hlmSidebarHeader`，照 shadcn 侧栏的 team switcher，模板的区段切换器即此写法，窄屏随侧栏收进抽屉）；或放在页头右侧，页头窄时收成 44px 图标按钮，名称视觉隐藏、仍是按钮的可访问名，`title` 给全文。页头其余只放侧栏触发器、面包屑与全局工具（搜索、主题、通知、语言、头像）；页头窄时收起主题与语言（在个人设置的偏好里改），搜索与模拟状态只留图标。面包屑首项与省略号不收缩（参与收缩会被压到最小内容宽度，中文一字一行），上级收缩权重大于当前页，先截上级；当前页不设硬下限，否则多级上级时会被推出导航区裁掉。共同底线是 `default-header-touch.spec.ts` 的两种宽度，页头控件全开：390 宽手机上面包屑最近一级上级是 44px 触屏目标；636 宽页头（900 视口减去展开的侧栏）里首项单行、上级与当前页都留得住，两级上级时当前页仍在导航区内；两者页头都不溢出。放在页头的选择器列为可见控件，断言它在两种宽度下的形态，往页头加控件要让两例继续通过。顶栏布局没有侧栏，选择器放在导航条起始处，窄屏随导航收进抽屉。
- **布局按服务对象选**：管理平台面向内部员工，条目多、会增长、需要按权限整组裁剪，用侧栏（`DefaultLayout`）；工作空间面向业务用户，内容优先，用顶栏（`WorkspaceLayout`），菜单组默认靠左、用文字链接；标 `placement: 'end'` 的组靠右、以图标按钮呈现（与主题、通知、语言同排，名称放在提示与可访问名里），模板自带的分组都不标。工作空间的主导航超过 7 项，或需要分组标题与按权限整组裁剪时，把路由换回 `DefaultLayout`——菜单定义不用动。
- **导航与快捷入口标签不换行**：两行的导航项看起来像两个入口。顶栏导航放不下时，`workspace-nav` 按实际宽度从末尾把菜单项收进「更多」下拉（当前页在里面时「更多」显示当前态），窄屏仍走抽屉；标签写 1–2 个词。卡片式快捷入口用横排（图标在左、标签单行截断），列数由卡片最小宽度自动排（`grid-cols-[repeat(auto-fill,minmax(13rem,1fr))]`，最小宽度按图标、间距与最长的英文标签核算），不按中文定死列数。
