# 项目通用约定

本项目各端共同遵循的约定。后端具体规则见 [后端开发规范](./coding-backend.md)。
<!--#if (SpaFrontend)-->
前端具体规则见 [前端开发规范](./coding-frontend.md)。
<!--#endif-->

## 1. 语言

- XML 文档注释与代码注释用中文；面向运维的异常消息与日志消息用英文。面向最终用户的响应文案走本地化资源或英文默认文案，不受此限。
- 不硬编码密钥、令牌、密码或真实客户数据；敏感信息在日志与响应中脱敏。

## 2. Git 与提交

提交信息使用 Conventional Commits：`<type>(<scope>): <subject>`，常用 type 为 `feat`、`fix`、`docs`、`style`、`refactor`、`test`、`chore`。项目另有分支或提交规范时以项目规范为准。

## 3. 工程约束

每条正文是本项目的工程原则，`例` 是在本项目技术栈中的落地。带 ⚠️ 的条目难以及时发现，必须遵守。

### 3.1 开发前查找参考链路

实现新功能前，从现有代码选 1~2 个最接近的端到端链路，沿用其分层、命名、目录、错误处理和 Mock 方式。参考范围覆盖前端组件、服务、契约、后端入口、应用与领域逻辑、持久化和迁移；存在疑问时以参考实现为准。

### 3.2 守卫按聚合范围分层

一条校验放哪层，取决于它约束**单聚合内不变量**还是**跨聚合关系**：

- 只需**单个聚合自身状态**即可判定 → 放**领域层**（领域服务/实体方法）。
- 需**跨聚合**校验（依赖其它聚合的存在/状态）→ 放**应用层**：领域服务不引外聚合，此类校验必须上提。

### 3.3 验证在入口 DTO 层完成

- 字段验证优先在**入口 DTO** 用注解完成（必填/长度/范围）；应用层、领域层**信任 DTO 已保证的前置条件，不重复校验**。
- **例外**：实体构造函数若存在**不经该 DTO 的第二条调用路径**，其守卫是多入口共享的不变量保护，**合法保留**。

### 3.4 新增能力优先扩展现有抽象

- 需要新能力时先问"**现有抽象能不能扩**"，扩不动才新增接口；需要外部能力时在既有抽象上加方法，**不在应用服务里直连外部 SDK/客户端**。
- **杜绝并行的第二套实现路径**：同一件事不该有两处判断分支。

### 3.5 抽象在内层、依赖只向内

- 依赖只能向内：领域层不依赖任何上层；应用/基础设施/表现层向内依赖。
- **接口定义放领域层，技术实现下沉外层**；应用/领域层需向外"下发"动作时，**在内层定中性抽象接口、由外层适配器实现**（依赖倒置），禁止内层直接引用外层类型。
- 反复出现的信封/载荷用**不可变值对象统一定义一次**，不散落多套。

> `例`：`IRepository`/第三方服务接口定义在 `Leistd.Ddd.Domain`，EF/Redis 等实现在 Infrastructure；应用层若需下发指令，定 `ICommandSender` 抽象、由 Api 层适配器实现。

### 3.6 删除幂等且保留真实失败

删除本地或外部资源时，**只把「不存在」当成功**（重试安全），**其余错误一律上抛**，让调用方中止后续删库/落库——杜绝"本地已删、外部仍在（仍计费/占用）"的孤儿资源。

### 3.7 是否触达真实外部端由统一开关决定

是否真正调用外部/云端，由**统一开关**（如 dry-run 配置）决定，**不靠调用方（尤其前端）传 opt-in 参数**。同一操作在不同调用方下行为一致，开关集中在一处。

### 3.8 枚举只在边界转换

- 领域内部状态用**强类型枚举**，不散裸字符串；**枚举 ↔ 对外契约串的转换只发生在边界**（序列化/handler 层），不下沉进领域、不上浮进无关层。
- **对外契约的分类/枚举字段（`channel/mode/scope/type/status` 之类）出入参与 JSON 命名策略一致**（camelCase：`orders`、`twoFactorRequired`）；内部枚举 PascalCase，只在边界一处转换。⚠️ 此类大小写不一致隐蔽、联调期才炸。

### 3.9 接口/实现签名同步；导入用短名

- 接口与实现类**签名同步改**，不留漂移。
- 一律**文件顶部导入 + 用短名**，禁止在代码正文内联全限定命名空间；同名歧义用 `using` 别名。

### 3.10 项目决策项

DI 生命周期与注册方式见 [后端开发规范 §4](./coding-backend.md#4-依赖注入)；对象映射见 [后端开发规范 §6](./coding-backend.md#6-数据访问)。对不同外部系统的序列化命名风格按其契约在字段上显式标注，不逐处自由发挥。
