# 覆盖率门槛：制定引导（非预置默认值）

> 本文件**不预置任何具体门槛数值**——覆盖率门槛是项目偏好、非通用机制，须由项目自行约定。
> 用法：项目 `docs/standards/test.md` 尚未定义覆盖率门槛时，按下面的**提问清单**引导用户约定，把结果沉淀进 `docs/standards/test.md`；**之后以该文件为唯一权威，不再回落本引导**。

## 制定时需与用户约定的维度（逐项问，不替用户拍数值）

1. **是否设硬门槛**：本项目要不要设覆盖率硬门槛？还是暂时只作建议、不阻塞？
2. **各类覆盖率要求**（若设门槛）：行 / 分支 / 函数 / 语句覆盖率，各要求多少？（可只选其中几项）
3. **关键代码更高要求**：核心业务 / 安全 / 支付 / 数据转换等关键代码，是否要求更高（如接近 100%）？范围如何界定？
4. **不达标的处置**：低于门槛时是**打回重做**、还是**告警+风险记录后放行**？
5. **落地位置**：门槛写入项目测试配置（如 `.runsettings` / `vitest.config`）还是仅记录在 `docs/standards/test.md`？

## 沉淀

用户答复后，把约定写入 `docs/standards/test.md` 的覆盖率章节（含数值与处置策略）。此后 test-runner 以 `test.md` 的门槛为准核对；无 `test.md` 门槛且用户未约定时，覆盖率仅作建议、不阻塞（见 test-runner reconcile 降级）。
