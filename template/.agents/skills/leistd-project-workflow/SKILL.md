# 项目协作

## 建立事实

1. 定位版本库或工作区根目录，检查当前分支、已有变更和用户最新约束。
2. 依次核对源码、配置、依赖清单、测试、CI/CD 和实际运行入口。
3. 读取 `docs/README.md` 及当前任务直接相关的规范、需求、模块、指南或部署文档；不存在时继续执行。
4. 参考邻近实现和最新的同类文档，不从模型记忆猜测项目 API、命令或约定。
5. 事实冲突时以当前可执行实现为准，并在本次改动中修正失效的权威文档。

不假定 `CLAUDE.md`、`AGENTS.md` 或其他工具专属入口存在。若项目已有此类有效约束，可作为补充事实读取，但不能将其作为唯一入口。

## 前端任务

修改前端代码时读取 `docs/standards/coding-frontend.md`。涉及 Spartan 组件、`components.json` 或 `libs/ui` 时使用项目内 `spartan` Skill，按其入口核对锁定版本和本地组件，不在此重复组件工作流。

验证按改动选择：文案只检查内容、链接与格式；代码运行相关 lint、测试和构建；组件升级或交互变化再检查组件健康状态和真实浏览器行为。项目文档只保留当前工程事实。

## 路由意图

以用户的最终意图决定交付边界：

| 意图 | 交付结果 | 按需读取 |
| --- | --- | --- |
| 只要分析、需求或方案 | 明确决策、风险、验收和实施步骤，并说明尚未实现 | [规划与实现](references/development.md) |
| 要求实现、修复或重构 | 完成可观察行为、风险匹配的验证和必要文档同步 | [规划与实现](references/development.md)、[审查与测试](references/quality.md) |
| 只要代码审查 | findings、证据、未检查范围和残余风险 | [审查与测试](references/quality.md) |
| 只要测试或定位故障 | 可复现命令、结果、原因和未覆盖范围 | [审查与测试](references/quality.md) |
| 跨会话、多任务或多人协作 | 以真实产物和验证证据跟踪每个完成条件 | [规划与实现](references/development.md) |
| 部署、发布、迁移或回滚 | 完成获准操作、健康检查、核心路径和回滚判断 | [部署与迁移](references/delivery.md) |

涉及文档创建、归属或去重时读取 [文档沉淀](references/documentation.md)。用户明确要求初始化协作规范，或缺失文档已经影响长期协作时，再读取 [项目协作初始化](references/bootstrap.md)。

## 执行闭环

1. 按用户最终意图和对应 reference 完成工作，不把计划或编译成功当作行为已验证。
2. 检查变化是否影响 API、权限、持久化、配置、Mock 或部署资产，按影响面同步。
3. 从最小相关检查开始验证，汇报实际结果、未验证项与残余风险。

辅助的规划、审查、测试或部署步骤不转移最终交付责任。用户要求实现时，应持续负责到行为和必要验证闭环；用户只要求方案、审查或测试时，不擅自扩大范围。

## 缺失文档

缺失规范或文档不阻断低风险任务。先从源码、配置、测试、CI 和邻近实现恢复事实；不要凭记忆重建规则，也不要为完整感批量生成目录、模板或报告。

产生需复用的规则或决策时按 [文档沉淀](references/documentation.md) 更新权威文档，否则只在结果中说明必要假设。

## 风险边界

执行不可逆或会影响外部系统的动作前获得明确确认，包括生产部署或回滚、共享或生产数据变更、密钥与真实客户数据操作、产生费用、流量切换，以及用户尚未决定的高影响方案。分析、代码修改和隔离环境验证可在已确认范围内继续。
