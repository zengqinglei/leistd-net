# 部署与迁移

## 建立交付事实

读取实际流水线、容器与编排配置、环境配置来源、应用启动代码、迁移、健康检查和最新部署文档。不要从通用模板猜测命令、拓扑或数据库策略。

## 执行流程

1. 明确目标环境、版本、变更范围、依赖、停机要求、成功判据和回滚触发条件。
2. 验证构建产物、必要测试、配置来源、权限、可观测性、备份和恢复能力。
3. 查明数据库由应用启动、流水线还是独立任务迁移。应用启动会自动迁移或创建数据库时，将部署本身视为数据库变更，不重复执行迁移命令。
4. 审查迁移内容、执行身份、超时、并发实例启动和失败恢复；数据库回滚不可行时明确前向修复策略。
5. 在隔离环境按授权执行。生产部署、流量切换、回滚、重启、真实数据操作和密钥使用前获得明确确认。
6. 执行后验证版本、健康检查、日志、数据库状态和核心业务路径；失败时优先保护数据并按已确认方案处理。

流水线和平台日志是单次部署证据。只有会被重复使用的环境事实或操作方式才更新部署文档，不生成固定部署报告。
