# 审查与测试

## 代码审查

1. 确定审查基线、变更范围和相关规范，读取完整 diff 与受影响调用链。
2. 优先检查行为错误、边界条件、安全、权限、数据一致性、并发、兼容性和缺失测试。
3. 先按严重程度列出 findings；每项包含文件位置、影响、证据和可执行修复建议。
4. 没有发现时明确说明，并列出未执行检查和残余风险。

用户只要求审查时不要擅自实现功能。为确认 finding 可运行最小检查，但不要把局部验证描述为完整回归。

## 测试与故障定位

1. 根据变化行为、验收条件和风险选择单元、集成、端到端及手工验证范围。
2. 先运行最小相关测试获取反馈，再按影响面扩大；运行时语义应通过真实宿主或项目既有测试服务器验证。
3. 失败时保留命令和关键日志，区分产品缺陷、测试缺陷、环境问题和外部依赖。
4. 补充测试时沿用现有框架、fixture 和断言风格，验证对外可观察行为及必要拒绝路径。
5. 汇总通过、失败、跳过、未覆盖范围和残余风险。

不得删除有效断言、静默跳过失败、伪造依赖或把未执行测试写成通过。测试结果默认由当前答复和 CI 承载；只有形成长期测试规则或重复操作时才更新权威文档。
