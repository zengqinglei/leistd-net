# 按开发场景选择验证：首批实现与证据

本轮基线为 develop `549d106d`，实现和最终候选验收归档在 [MR #36](https://github.com/zengqinglei/leistd-net/pull/36)。报告中的首个候选为 `8ee2a271`；最终候选还减少范围规划的额外网络准备，其准确 SHA、后续运行与净指标以 MR 验收记录为准。不同输入的单次 CI 不作为成对实验或稳定 SLA。

## 改造内容与责任

| 变化 | 原行为 | 本轮行为与保护 |
| --- | --- | --- |
| 内部文档 PR | 运行 Framework、打包/消费、真实 PG/OIDC、三片六场景 | 实际 workflow 白名单判定，仅完整静态、范围规划和必过汇总；动态明确“不适用” |
| 普通代码/交付输入 PR | 完整 PR 档 | 保持完整档；范围未知、混合改动、随包或生成文档均不能享受内部文档例外 |
| 三项模板源码预检 | 总静态入口一次、每个分片再一次 | 总入口一次；CI 分片显式接替，核对清单且汇总必须核对静态成功；默认人工入口仍预检 |
| 质量汇总 | 只直接等待模板分片和包消费 | 等待并核对范围、静态、打包、Framework 测试、包消费、PG、OIDC、分片，并验证完整回执 |
| 业务项目规范 | 已允许按风险收窄，具体开发场景不足 | 项目测试规范明确小修复、新模块、跨模块等范围；项目 Skill 引用唯一规范 |

白名单唯一配置在 `ci.yml` 的 `template-slice-plan/scope`，不根据 `.md` 扩展名猜测。差异是实际 base→checkout SHA，关闭 rename 检测，未知/空范围全量；复用调用即使继承 PR 事件，也因显式候选输入而不能使用 docs-only。规划复用已有作业，不新建 runner。

审计、真实浏览器、场景 Backend/Runtime/Lint/Frontend/Test、数据库隔离、独立 hive/feed/缓存和 immutable 候选包均保留。普通小 bug 代码 PR 仍完整执行，不能将 docs-only 收益用于所有开发场景。

## 去重的净成本

本地同快照、交替三轮运行实际预检函数，与 CI 接替清单入口比较，两者均包含 pwsh 启动与同一解析包装：

| 入口 | 全部秒数 | 中位秒 |
| --- | --- | --- |
| 原三项预检职责 | 12.700 / 10.959 / 11.028 | 11.028 |
| CI 清单接替（包括 `check-all -List`） | 1.958 / 1.739 / 1.737 | 1.739 |

入口中位少 9.289 秒，三片约 27.867 runner 秒是本地估算；不把它当整条 CI 墙钟收益。历史 30 分片预检中位 11.344 秒是毛收益估计，不能忽略新增清单检查。

首个实现规划作业运行 10 秒，其中 scope 5 秒；pack 在起点后 15 秒启动，存在新增规划依赖。静态在起点后 60 秒完成，早于最后关键分片结束，对汇总新增静态依赖未拉长尾部。新增规划成本可能抵消单片去重墙钟收益，最终实现将规划 checkout 深度改为 2，直接取 PR merge 父提交，保留缺失时补取/全量的保守语义；最终实跑成本归档 MR #36。不能只统计删除命令，也不能把不同作业的节省相加当墙钟收益。

≤510 秒继续作为代码 PR 的中位目标。首个实跑恰为 510 秒，只证明一次观测在预算内，不能宣称稳定达标。runner 合计与墙钟完整披露；可归因的新增成本吞掉收益时修正，不用十秒级去重重新进行高噪声分片重排实验。

## 缺陷检测与默认入口验证

- 实际 workflow 步骤的隔离 Git 夹具覆盖内部文档各白名单入口、随包/生成文档、混合和多提交、跨边界移动/删除、大小写、Unicode、未知基准、空/失败 diff、dispatch/复用事件。去掉 `--no-renames` 可重现漏判，恢复后拒绝。
- 实际汇总步骤拒绝范围/静态和每个必要动态作业的 failure、cancelled、缺失或错误 skipped，以及非法范围值。移除静态成功要求可重现假绿，恢复后拒绝。
- 三类隔离源码变异：未定义条件符号、条件守卫内的 `InternalsVisibleTo`、动态连接路径 `GetAwaiter().GetResult()`。原检查器、默认人工矩阵、接替总静态入口均非零并给出目标诊断；人工矩阵在 audit/pack/generation 前拒绝。CI 分片可继续，但实际汇总对静态 failure 拒绝。
- 总入口删除任一三项预检时，CI 清单接替拒绝；人工使用 CI 跳过开关拒绝。撤销变异后原检查器、总静态、清单合法对照恢复绿。
- 本地变异入口共 28 条记录均符合预期退出码；聚合正反例另行执行。完整静态闸门 30/30、actionlint v1.7.12 和官方项目 Skill 校验通过。
- 本地实际生成 `identity-all-features` 与 `resource-localization`，确认项目测试规范存在、项目名替换正确、Skill 的相对引用解析到实际项目文档；六场景实际生成/构建/测试还由候选 PR CI 验证。

回归入口只在相应维护改动时使用：`python scripts/test-workflow-change-scope.py` 和 `python scripts/test-template-source-preflight.py`，不增加每次功能开发必跑的日常闸门。原始退出码、诊断、命令、耗时、manifest、API 状态、CI 日志和回执存于本机隔离 `.tmp/quality-selection-20261003/`，远端运行链接与最终记录归档在 MR。
