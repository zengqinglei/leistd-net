### 3.1 分片数量的计算规则

对固定输入与模式，令 `S`／`T` 为前置及汇总耗时，`F` 为独立必要作业时长，`h` 为实测每片准备成本，`L_i(k)` 为 k 片装箱后包含经证明的去重及证明成本、保留全部适用责任的负载，`D(k)` 为该分配下扣除首次检查和证明成本的净节省，`C_i(k)` 为冷启动修正。先从场景权重剥离原来首位的冷启动增量，再按新分片首位计入 `C_i(k)`，避免重复计费。runner 的增量冷启动成本记为 `ΔC(k)`。

- 墙钟约束：`S + max(F, max_i(L_i(k) + h + C_i(k))) + T ≤ 510`；参数随固定输入校准，不把旧63／11秒当常数。
- runner约束：`D(k) ≥ (k−3)×h + ΔC(k)`；三片重新分配也要核对冷启动及准备差异。若实际准备成本不相等，使用各片成本总和之差替代平均值公式。
- 完整模式在未修正冷启动的理想下界中，单片场景负载需≤379秒；五／六／七片分别至少需要约320／171／228秒净节省。前端15产品改四片至少需要抵消约49秒新增准备。下界不能代替实际装箱与首次候选校准。
- 没有经证明的 `D(k)` 时按0计算。本轮默认 PR 三片；只有 P1／P2 已给出合格净收益，才从三片至必要场景数的有限候选中，按同一确定性算法计算并选择满足两项约束的最小 k。新增分片还要求名义墙钟及现有模型的20%后置时长敏感性均≤510秒；这是预先固定的筛选余量，不是测得的置信区间。不为候选 k 分别启动 CI 试跑。
- 无可行 k 就保留三片均衡，登记预算缺口；不放宽 runner 要求，不启动为证明510秒失败而重复跑全集的实验。full仍保留两片，不由 PR 预算驱动增加。

最新日志中，三个作业的首次 `npm ci` 相对后续中位数分别约−0.15／0.13／0.08秒，首次 restore 约多5.44／4.56／6.82秒。这些是命令区间差异，不能证明因果冷启动成本，也不支持直接采用历史“每新增一片20–25秒”。P1 以当前输入校准，未知成本保守处理；876秒及414秒仍是待验证预测，三片也不能预先保证 runner 中性。

已有日志中 `info`、`healthcheck`、lint的累计区间约267秒；即使全部省掉，也小于五片名义达标所需的320秒，实际还必须保留各类输入的首次检查。因此仅这三项去重不能保证完整PR达标。实施中须用真实净收益重新计算；不存在可证明且成本合理的方案时，明确保留完整PR预算缺口，不用推算包装成终局已经达成。

## 4. 实现设计

### 4.1 同候选阶段去重

1. 先做一次静态前置判定：读取已安装工具源码／官方说明，以可复用生成产物按阶段实际输入摘要分组，优先审视 `info`、`healthcheck`、lint。旧产物只用于排除不值得追踪的假设；与当前输入不一致时不能作为等价证明。不为去重调研另跑18场景全集。
2. 等价条件包含生成文件及目录存在性、配置、锁文件、工具版本、命令参数、运行平台和必要环境。工具读入项目源码时必须纳入完整范围；路径或项目名称会影响结果时不能随意归一化。
3. 进入 P2 必须同时满足：至少两个场景的阶段输入可证明等价；同片执行扣除首次检查、摘要与来源校验后仍有净收益；保守收益足以改变第3.1节的可行分片或预算判断。缺少证据、无等价组或收益不足，P2以“无合格项”关闭，不增加回执来源字段、通用摘要系统或试验开关。
4. 合格阶段优先使用最简单的责任安排。确属项目无关的检查可按分片执行一次，并由片级结果明确承担该责任；读取项目源码的检查不能因此降为片级。需要接替时仅在同一候选、同一隔离runner复用成功结果。失败、取消、缺少结果或未知读取规则时完整执行。现有audit去重和源码预检接替不重复计收益。
5. 业务行为测试、真实运行冒烟、PG／OIDC和容器本轮逐场景按责任执行，不建立行为结果缓存；npm安装不以另一产品的可变 `node_modules` 接替。
6. 仅对合格接替记录执行者、实际输入摘要、命令、环境和结果。被接替者注明来源；禁止把没有执行、没有有效来源的阶段直接写成 `pass`。片级检查也必须有本候选真实执行的结果，不以虚构逐场景成功代替。
7. 实测未达到前置净收益门槛时移除候选实现，不留迁移开关；无合格项就保留原执行并如实报告。

Claude核对的上一轮产物为15种不同前端树、18种不同后端树，另有3个无前端产品，说明整棵产品复用不成立。但整棵树不同不能推出每个工具读取的输入投影都不同，且这不是当前基线的重新生成结果。本轮不预记去重收益，也不据此宣称所有阶段绝无等价输入。

### 4.2 最终执行分片

- 第3.3节实测未通过联合门槛，均衡候选撤回；完整、前端和后端模式统一使用登记逻辑组与所选场景的交集，保留登记顺序。
- 场景、档位和逻辑组仍唯一维护在 `template-matrix-scenarios.ps1`，不复制清单，不保留未使用的成本字段、LPT算法或调度切换开关。
- PR最多三组、full最多两组；局部只创建非空交集组。候选计划以明确成员和容器列表绑定实际执行责任。
- 模型和实测均不支持当前完整PR的510秒联合目标。保留全部必要检查及预算缺口，不自动增开runner或追加样本。

### 4.3 计划、回执与必过汇总

- 逻辑场景归属继续用于覆盖和人工按组验证；CI实际执行组由候选计划明确列出ID、场景集合、模式和容器责任，workflow仅消费该计划。
- 更新计划schema到一个明确的新版本，同时更新所有生产读写者及夹具；不保留新旧CI解释器、静默字段推断或迁移开关。本地选景输出继续与CI计划分开。
- `Read-QualityValidationPlan` 校验候选、档位、模式、唯一且完整的分配、合法成员及责任；汇总从独立预期计划核对，不能由执行回执自行决定范围。
- 汇总拒绝少片、重复片、少场景、重复场景、跨组移动、错SHA／档位／模式、非法不适用、失败／取消，以及缺少适用容器责任。
- 有去重时核对真实执行来源与相同输入；伪造来源、来源缺失／失败／不同候选或摘要不一致均失败。没有去重则不引入空的通用证明系统。
- 原有 `-Scenarios` 和人工分组入口保留其职责；计划驱动入口不能与手动跳过混用。最终CI直接使用新调度，不长期并行运行旧调度。

## 6. 验证与成本控制

### 6.1 开发中验证

- 使用现有真实Git／生成夹具，覆盖前端8／15、后端9／11／18、混合源码、共享配置、未知输入、删除、重命名、多提交、脏树和无效基线。
- 调度负例覆盖空片、同逻辑组的局部交集、重复／遗漏／未知成员、模式与容器责任、错误版本／SHA及来源；同时保持覆盖闸门及默认保守执行。
- 接替用可执行、能定位目标诊断的缺陷注入，含恢复后绿；无需增加镜像／数据库去证明纯调度。
- 按改动运行现有plan／scope夹具，最终一次 `check-all.ps1`。不为同一无关输入反复执行本地18场景全链。

### 6.2 远端验证

1. 封存预期、范围与测量方法，完成代码后跑一个真实完整候选PR；检查实际计划、全部回执及每阶段用例，不以标题或模型推断执行成功。
2. 同候选性能预测与实际分解对照；偏差先定位到排队、准备、具体场景或装箱，修复时只跑必要反馈，不盲目重跑全集。
3. 分开判断两项验收：首轮确认同工作量调度改善且 runner 有希望不增加后，才补固定前后三轮，验证调度收益；即使完整PR仍超过510秒，也可完成这项测量。只有模型与首轮均支持双指标可达，才以这组数据验收510秒目标，不另开重复三轮。保持同生产输入、同runner规格、同责任和明确缓存条件；隔离测试候选允许实现不同，生产不保留旧调度开关。
4. 旧样本只有满足上述条件才计入，三次不同SHA／工作量的历史运行不能代替。候选首轮若满足固定条件可计入三轮，不额外再跑一次。
5. 局部场景先用真实生成／阶段回归证明责任。远端先选后端角色文件对应18产品这一类有希望达标的输入，最多先验收一类；没有真实业务PR时可使用明确标注的隔离CI验收PR，不假称真实业务交付。
6. 合入后核对同SHA的full、实际发布包／tag／Release。生产业务部署不在仓库CI优化的验收范围。

完整PR三轮基线＋三轮候选约需1.95万 runner 秒，即325 runner分钟，是一次性验收成本，不是墙钟等待时间，也不含局部验收和发布。符合固定条件的首轮计入三轮；不对每个尝试各跑六轮。首次远端没有调度改善或 runner 明显增加，先用日志修正，不启动重复性测量。预测不可能达510秒时，不为这个结论单独增加稳定性测量。不能通过减少必要验收把一次观测改称稳定收益。

## 7. 验收标准

| 维度 | 标准 |
| --- | --- |
| 功能与质量 | 既有输入选择、覆盖要求、实际依赖和失败阻断全部保持；适用阶段可追溯到本候选真实执行 |
| 维护性 | 场景单一登记；一套计划schema和CI调度；没有平行清单、可变目录共享、未启用开关或双重校验 |
| 调度改善 | 同生产输入、同责任前后三轮墙钟中位下降且runner中位不增加；完整PR名义预期1335→876秒、约34.4%，以实测为准，独立于510秒目标登记 |
| 局部预算 | 被选定验收的局部输入固定三轮墙钟中位≤510秒；同输入runner中位不增加 |
| 完整PR预算 | 当前完整责任固定三轮墙钟中位≤510秒且runner中位不增加；只满足其中一项不算达标 |
| 报告 | 全部样本、工作量、缓存条件、用例／场景、墙钟、runner、一次性验收成本和未执行事项完整披露 |
| 审查与交付 | Claude审查无剩余必须修复项；最终候选CI成功；获准合入后同SHA full与发布成功 |

优化交付完成和完整PR预算达标分开登记。如果有质量、维护性或局部收益，但完整PR双指标仍未达，明确保留该历史目标，不放宽标准、不宣称所有任务关闭；继续优化需依据新的实际瓶颈和成本判断。

完成后将实际成立的调度／证据规则上收到稳定QA，更新确有长期价值的已有根报告并删除本计划。Skill入口未失效则保持；若实际需要调整，按官方 `skill-creator` 与官方定义验证，不复制调度算法到Skill或业务项目文档。
