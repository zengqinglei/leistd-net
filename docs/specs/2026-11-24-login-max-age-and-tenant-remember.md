# 授权端点 max_age 边界与登录页记住租户的时机

状态：已完成 · 风险档：中 · 关联：#316

## 1. 需求

### 问题与背景

下游按 OIDC 规范和登录交互的通行做法核对模板，提出两条对齐建议，都不是缺陷：

1. **max_age 边界。** `ConnectController.AuthorizeAsync` 用 `now - authenticatedAt >= maxAge` 判超期，经过时间恰好等于正数 `max_age` 时也要求重新认证。OIDC Core 1.0 §3.1.2.1 规定"经过时间大于该值"才必须重新认证，模板比规范严一秒。`max_age=0` 按 `0 >= 0` 恒超期，等同 `prompt=login`，这一部分是正确的。下游自己写的判断曾因"距今 ≤ max_age 算新鲜"，在同一秒放行过 `max_age=0`，模板没有这个问题，修改时必须保住它。
2. **记住租户的时机。** 本地身份形态下，`TenantContextService.set()` 在登录页确认租户时就写入 `localStorage`，这时凭据还没提交。手选错租户且登录失败后，刷新或下次打开登录页仍会预选这个错的租户。通行做法是只记住上次成功进入的组织，未成功的尝试不改变下次的默认值。

### 目标与非目标

- 目标：正数 `max_age` 的边界与规范一致，`max_age=0` 仍恒要求重新认证；登录页只在凭据被接受后记住租户。
- 非目标：
  - 退出登录时是否清掉记住的租户，沿用模板现有口径，本次不改。
  - 资源服务形态（租户只来自已验证会话）不涉及。

### 功能要求与验收

| # | Given | When | Then | 覆盖 |
| --- | --- | --- | --- | --- |
| R1 | 会话的认证年龄恰好等于正数 `max_age` | 发起授权 | 照常签发 | `OpenIddictLifecycleTests`（可控时钟） |
| R2 | 认证年龄比 `max_age` 多一秒 | 发起授权 | 回登录页，要求重新认证 | 同上 |
| R3 | 同一秒刚登录 | 以 `max_age=0` 发起授权 | 回登录页，要求重新认证 | 同上 |
| R4 | 记住的是租户 A，用户手选租户 B | 凭据被拒 | 存储仍是 A；内存里仍是 B，可以改正后重试 | `login.spec.ts` |
| R5 | 同上 | 口令被接受（包括还要走第二步） | 存储改为 B | `login.spec.ts` |
| R6 | 记住的是租户 A，用户清除租户回到宿主 | 凭据被接受 | 记住的租户被清掉 | `login.spec.ts` |
| R7 | 域名指向的租户不可用或指向宿主，或 401 带租户失效头 | — | 内存与记住的租户一起清掉 | `login.spec.ts`、`http-error-interceptor.spec.ts` |

方案：

- **R1–R3**：判断改为 `!fresh || maxAge == 0 || now - authenticatedAt > maxAge`。
- **R4–R7**：
  - `TenantContextService` 的 `set()`/`clear()` 只改内存，另加 `remember()`（凭据被接受后持久化当前上下文，宿主则删除记录）和 `forget()`（内存与存储一起清）。
  - 口令登录在 `login` 返回后调用 `remember()`。这一步包括还要走第二步的情况，因为第二步页刷新后也要带对租户。通行密钥登录在 `onSignedIn` 开头调用。
  - 外部登录要整页离开，提供商那边的结果回不到登录页，所以在跳转前 `remember()`，与原行为一致。
  - 域名探测判定租户不可用或指向宿主，以及 401 带租户失效头时，改用 `forget()`。

## 4. 结果

- **交付：** #316（合并提交 `0c06629e`），与同轮其他下游反馈一起合并。
- **偏差：** Codex 审查提出"登录请求在途时还能切换租户，会让记住的租户和第二步对不上"。最初的方案是发起时捕获租户、再一路传下去；用户认为这是过度防御，最后改为：
  - 认证在途时禁用租户切换入口，与"提交在途禁用"的常规做法一致；
  - 登录页销毁后，不再处理认证响应：不记住租户，也不导航。
- **已知局限（用户确认不修）：** 账号 A 的凭据已通过、"读取当前用户"的请求还没返回时，用户离开登录页，改用账号 B 完成整套登录。如果 A 的这个请求最后才到，界面上的当前用户会暂时显示为 A；服务端会话仍是 B，请求也按 B 处理，下次刷新当前用户时自动纠正。要触发，A 的一个读取请求得比 B 的整套登录还慢，概率几乎为零，而且只影响显示。
- **验收：**
  - `Max_age_boundary_follows_the_specification` 做过变异验证：改回 `>=` 后，"恰好等于"那条失败；
  - 登录页 spec 覆盖 R4–R7，以及"在途禁用切换""离页后不收尾"；
  - 全场景矩阵 CI 通过。
- **已上收的常驻文档：** 无。行为规则写在代码注释与 spec 里，模板规范本来没有登录页记住租户的条目。
