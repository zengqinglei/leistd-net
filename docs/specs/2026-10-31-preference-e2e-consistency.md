# 登录偏好端到端一致性

状态：已完成 · 风险档：中 · 关联：[PR #213](https://github.com/zengqinglei/leistd-net/pull/213)

## 1. 需求

用户于 2026-10-31 确认：语言、主题属于界面偏好，本设备记住最后一次生效的值。这推翻了已确认的“账户语言只在内存、主体离开退回设备语言”设计，取代前一规格②的认证页遮罩方案。设备记忆避免每次登录和退出重复切换；账户优先仍保留个人、组织和部署默认的管理能力。

| 场景 | 决定与验收 |
| --- | --- |
| 未登录选择后登录 | Given 设备已有语言、主题，When 登录且账户无值，Then 保持设备值，不自动写入账户；账户有值则进入目标页时生效。 |
| 登录后修改 | Given 已登录，When 在页头或个人设置修改并保存成功，Then 账户响应立即生效，同时记在设备。 |
| 退出、重开浏览器 | Given 已生效账户语言与主题，When 主体离开或浏览器重开，Then 登录页保持最后生效值。 |
| 组织默认 | Given 用户无个人覆盖，When 登录读到组织语言与时区，Then 在进入目标页时应用，语言记在设备。 |

后端设置定义与 Mock 的账户主题默认值留空，显式 `system` 仍表示跟随系统；否则未设置账户外观也会覆盖设备值。归属 Template；沿用 `app_lang`、`theme_config`，不增加存储键，按源隔离，SSO 的身份与资源应用分别记忆。不调整框架工作单元改动，不改下游仓库。

采用准备与提交分离：现有语言服务准备全局、已访问及目标路由首次访问的词条，路由解析同时加载活动语言和待生效语言。会话上下文先建立权限与设置，在本次导航链成功的 `NavigationEnd` 同步提交偏好，随后提示成功；拒绝、失败、跳过时释放准备结果。语言加载失败保持原语言，主题与时区独立生效。启动与同主体后台重查保留直接应用入口。

验收由偏好、语言、会话、返回地址及登录入口定向 spec 覆盖；真实 Router 验证首次渲染、守卫拒绝、解析失败、UrlTree 改道以及首次功能词条延迟与失败；生成项目 Mock 浏览器人工验收设备记忆与首帧。

## 4. 结果

实现设备记住最后生效的语言、主题，登录导航准备与提交分离；撤下认证页遮罩，恢复外部回调处理文案。后端和 Mock 的未设主题返回空值，个人设置展示设备当前主题；显式跟随系统仍可选择。首绑守卫返回 UrlTree 的改道同样延后提交。

本地化与非本地化生成项目的定向回归、真实路由首次渲染、PostgreSQL 账户偏好与设置契约、有头 Mock 浏览器验证通过。浏览器确认新设备从英文登录页直接进入中文目标页、同设备再次登录与退出保持偏好。同步设置规范、多语言规范、文档索引及服务注释。实现见 [PR #213](https://github.com/zengqinglei/leistd-net/pull/213)，合并与 CI 证据随 PR 记录；未改下游三仓，不发布正式版。
