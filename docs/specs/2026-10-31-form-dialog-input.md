# 表单、弹窗与输入行为

状态：已完成 · 风险档：高

## 1. 需求

2026-10-31 确认统一修复 A01–A20（A16 保持既有行为）。业务表单使用 Signal Forms submit，提交时展示全部错误，字段错误回填并按可见 DOM 顺序聚焦；仅请求中或业务前提不成立时禁用。非口令标识先规范化再校验，敏感值保持原样。

业务编辑弹窗禁止外点关闭；有修改时 Esc、关闭与取消确认放弃，保存中锁定这些入口。异步内容使用等高占位和不抢焦点的迁移；短视口正文可滚动且操作始终可达。OTP 接入 FormValueControl 与 Field；自动保存保留逐行错误反馈的例外。

验收：Given 空表单，When 点击或 Enter 提交，Then 所有错误可见且首错获焦；Given 延迟保存，When 再次提交或请求关闭，Then 不重入且不关框；Given 服务端字段拒绝，Then 字段显示原文并获焦；Given 修改草稿，When 请求退出，Then 继续编辑保留内容、放弃才关闭；Given 加载失败，Then 显示重试且不变成新建。自动化覆盖共用机制与各消费组件，390×667、组字和焦点使用 Mock 浏览器补充验证，Safari 和软键盘人工验收。

## 2. 方案

打开时静态封闭 Brain 自动关闭，隐藏内置关闭按钮，应用级共用关闭部件统一读取实时 busy/dirty 并调用 ConfirmService。该部件放 core/components，遵守 shared 不依赖 core 的边界。保存成功和销毁使用框架原有关闭路径。

表单持有者 await HTTP Observable，父级保存动作不吞错误。共用错误转换只匹配已声明顶层字段，其他路径使用显式映射；服务端错误返回 TreeValidationResult，submit 完成后渲染并按 DOM 顺序聚焦。OTP 转发 Field 的关联与失焦状态到真实 input。

## 3. 计划

1. 为现有缺陷建立先红后绿回归，交付共用提交、错误、焦点和关闭机制。
2. 迁移业务编辑弹窗及父级保存契约，接入页面表单、OTP、邮件测试、URI 和自动保存反馈。
3. 完成加载/失败/重试、输入语义、组字、短视口布局及规范同步。
4. 运行四场景生成、control 分片、两场景单测/lint、静态闸门与 Mock 浏览器验收。
5. 提交 PR、处理 CI，等待覆盖最终 head 的独立 Claude 通过结论后合并；不发布正式版。

## 4. 结果

统一提交、服务端字段回填与首错焦点、实时关闭闸门、OTP/Field、输入语义、异步加载/重试和短视口布局均已实施。保存动作输入命名采用 `saveAction`，避免与组件提交方法冲突并符合无输入别名规范；关闭部件放 core/components，以遵守依赖边界。

两种前端生成模式的全量单测、lint，四场景生成、control 分片、全部静态闸门与读取成本均通过。Mock 浏览器完成短视口、未保存确认、延迟保存关闭锁定、真实 Enter、CDP 组字及异步焦点验收。实际 Safari 补发 Enter、真实软键盘、全部能力开关组合与复杂叠层返回焦点仍待人工或后续专项验收。

长期规则已上收到 frontend-forms、frontend-ui、frontend-spartan 和模板文档任务索引。实现随本 PR 交付；独立审查与 CI 是合并条件，不发布正式版。
