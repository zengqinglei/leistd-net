# 弹窗高度在打开时确定，首次加载统一用骨架占位

状态：进行中 · 风险档：中 · 关联：待开 PR

## 1. 需求

### 问题与背景

用户实测发现两类不一致：

- **弹窗打开后高度跳动。** Spartan 弹窗默认垂直居中（brain `global().centerHorizontally().centerVertically()`），内容变化导致高度变化时，上下两条边各移动一半，标题和页脚都会跳。模板里只有 4 个弹窗固定了高度：用户编辑、租户详情、开放应用编辑、权限授权。打开后会变高的有 4 个：
  - Webhook 新建订阅：先加载整张表单，事件类型目录再单独加载；
  - 分配角色、批量设置角色：先转圈，再出角色列表；
  - 确认身份：在口令、验证码、通行密钥、重新登录四种形态之间切换。
- **加载态不统一。** `frontend-ui.md` 已规定首次加载用骨架，但多处在内容流里直接放裸 `hlm-spinner`：
  - 有的在正文左下角（角色列表末尾）；
  - 有的悬在一行右侧（事件类型区），被误认为鼠标在转圈；
  - 同类弹窗里，有的用骨架，有的用转圈。

### 目标与非目标

- 目标：
  - 弹窗高度在打开时确定，打开后不随加载、切换、选择而变；
  - 首次加载、重新加载、动作进行中三种加载态各有唯一的表现；
  - 规则写进生成项目的规范和审查清单，业务项目照此遵循。
- 非目标：
  - 不改成顶部对齐：跳动会转到页脚，而且偏离 Spartan/shadcn 的官方默认。
  - 手机上不做全屏弹窗：复杂编辑沿用抽屉。

### 功能要求与验收

| # | 规则 | 验收 |
| --- | --- | --- |
| R1 | 打开后内容会变的弹窗用固定高度，取能容纳各状态的最小档（`h-96` / `h-120` / `h-160`）；仍受 `max-height: calc(100dvh - 2rem)` 约束，正文内滚动；内容固定的短弹窗自适应 | 对比页 6 档视口实测；相关 spec |
| R2 | 有说明文字的字段出错时，错误替换说明，不新增一行 | 规范；审查清单 |
| R3 | 首次加载用骨架，占住内容最终的位置：弹窗、抽屉整块正文用 `app-dialog-loading`，区域内的目录用同形的行骨架；加载、失败、内容三者互斥 | spec：加载中出现骨架，不出现 spinner 与空态 |
| R4 | 重新加载保留内容并标忙；动作进行中用按钮内 spinner；只有整页处理过程（应用启动、外部登录回调）用居中 spinner | 规范；能写成不误报的 lint 规则时加上 |

方案：

- 4 个弹窗加固定高度档：Webhook 订阅 `h-160`，两个角色弹窗 `h-120`，确认身份 `h-96`（三种形态自然高度最高 360px）。两个角色弹窗补上最小宽度，窄屏下与其他弹窗一样宽 100vw−2rem。
- 12 处首次加载的裸 spinner 改成同形骨架，新增共享组件 `app-list-loading`（参数只有行数、是否带勾选框）。
- ESLint 限定 `hlm-spinner` 只能出现在 `button`、`a` 内；四个文件在配置里豁免：应用启动、外部登录回调、头像上传遮罩、设置自动保存。
- 规则同步到 `frontend-ui.md`（§1、§2.7）、`frontend-forms.md`（说明与错误互换）以及项目 Skill 的审查清单。
