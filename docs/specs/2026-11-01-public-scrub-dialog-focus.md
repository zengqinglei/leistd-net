# 公开内容、弹窗焦点与文档增量验证

状态：进行中 · 风险档：高

## 1. 需求

用户于 2026-11-01 确认跨 Framework、Template、Skill 与 CI 的本轮范围，策略复审通过后实施。

| 条目 | 验收标准 | 验证 |
| --- | --- | --- |
| 公开内容 | 给定全部跟踪文件与公开 PR 文字，清理下游名称、内部服务与专属业务信息后，技术结论与理由保留；后续引入相同表述会失败 | 现有术语闸门、全仓扫描与公开文字审稿 |
| 弹窗焦点 | 给定两档视口的三类表单，首尾及首末列控件聚焦时，外扩 3px 的焦点环完全在所有裁剪祖先的可见区域内；正文与标题左缘误差不超过 0.5px，无横向滚动，页脚可达 | 实际生成项目的浏览器几何测量与截图 |
| 文档增量 | 同一 PR 同基线的前一候选已通过，新增文档时只执行当前文档责任并承接成功来源；基线、来源或输入无法证明时回退原 PR 计划 | 质量计划、汇总核验与反例；本 PR 实际文档提交观察 |

不改 Git 历史、正式版发布流程和下游项目。公开文字改写须等最终候选审查通过；合并也须最终候选审查通过且 CI 全绿。

## 2. 方案

公开内容扫描复用现有术语闸门，词表为唯一豁免，不继承历史规格豁免。示例使用通用服务名，保留连接名归一化、多服务分库、并发与审计断言。

弹窗内边距由 Helm 的同一变量定义。滚动正文以等量负外边距与内边距扩展裁剪边界，表单用最小高度约束收缩；保留单层滚动和固定页脚。带按钮的徽章保留内部文字截断，外壳不裁剪子按钮焦点环；其他裁剪容器按实际控件与留白复核。

直接 PR 继续验证合并候选。文档增量只在 synchronize 中启用，固定同仓库、同 PR、同 workflow 对前一 head 的最新运行与 attempt，通过该次计划构件与成功汇总核对来源。目标分支基线必须相同，分支增量和合并候选完整差异均须属于已有文档分类。计划记录当前 head/base/候选、来源和责任链，汇总核验后才输出成功。证据缺失、失败、未知输入、目标分支前移或非祖先均回退原计划。合并后与发布候选计划不变。

## 3. 计划

| 产物 | 验证 |
| --- | --- |
| 中性文档、示例与防复发规则 | 全仓扫描、静态闸门、读取成本与 Skill 校验 |

| 计划器、汇总与 CI 说明 | 计划脚本正反例，固定候选与来源证据的拒绝验证 |
| 框架候选包与公开文字审稿 | 受影响组件测试、打包与隔离消费；审查通过后改写文字并按最终 head 合并 |

## 4. 结果

三项实现已完成。公开内容闸门覆盖历史规格与全部跟踪文件；服务示例与测试保持归一化、排序、分库和审计语义。新增可操作徽章的裁剪修复与真实几何回归。

本地受影响框架测试、打包与隔离消费、四个代表场景生成、control、静态闸门、读取成本、两种前端全量及失败文件定向复验、lint 与浏览器测量完成。新增 URI 焦点用例先失败后通过；浏览器对原弹窗裁剪的变异也能拒绝。CI 计划正反例包含固定来源、基线前移、错误身份、连续文档增量与汇总核验。

常驻规则已同步到 CI 放行、版本通知、下游反馈边界、前端界面与 Spartan 定制说明。历史提交和 tag 不重写；公开文字改写、最终候选审查、合并与 beta 结果以本 PR 的后续交付记录为准。
