# 工作单元控制库连接复用与登录偏好过渡

状态：已完成 · 风险档：中（本轮任务书指定，跨层验证）

## 1. 需求

本轮接收两项下游反馈，策略经两轮审查通过。交付涉及 Framework 与 Template，同一分支实施。

| 项 | 决定与理由 | 验收 |
| --- | --- | --- |
| ① F2 本地解析器提前创建控制库上下文 | 采纳，归 Framework。真实租户路由查询时新建异步释放的独立 DI scope，直接读取注册表，不经 Provider；避免占用调用方工作单元实例。无租户与控制库名保持快路径。 | Given 真实解析器、同目标且初始连接不同，When 事务中先业务后控制，Then 提交和冲刷后的回滚均原子生效；有租户路由也成立。 |
| ① F1 控制库回调 | 采纳 IdentityControlDbContext，归 Template。有活动连接时采用 ExistingConnection，否则采用创建上下文连接串或控制库配置。OpenIddict 当前由 EF 存储直接使用，不扩改无消费者的事务入口。 | Given identity 多租户 PostgreSQL，When 两种获取顺序 × 提交/回滚，Then 两类写入同成同败。 |
| ② 登录后语言在认证页切换 | 采纳，归 Template。设备语言与账户语言不同时每次登录都存在此路径。账户语言不持久化的共享设备设计保持。外观通常不变以同账号同设备且本地值未改变为前提。 | Given 不同设备/账户语言，When 凭据通过准备进入应用，Then 完整外壳在 clear 前进入中性遮盖，偏好及导航期间不露字，导航结束/失败后恢复操作。 |

沿用组件 signal、AuthShell、原生 inert 和现有 Spinner；不新增服务、状态机或配置。保留 #209 整页离开不建立账户偏好的边界。覆盖密码、第二步、两种通行密钥、强制首绑完成、外部回调（含历史会话探测与绑定返回安全页）。

### 方案与审查结论

首轮要求 M1 遮盖整个外壳并以 inert 隔离交互；M2 导航 resolve false、抛错均释放；M3 可控时序单测加桌面与窄屏浏览器实验。第二轮全部通过。实施核对：等待现有导航 Promise（包括 UrlTree 改道），不加延时或全局监听；统一 finally 覆盖 clear/loadUser/establish/导航；外部回调恢复保留返回登录出口。取消导航只恢复操作，不新增取消提示。

连接路由查询独立 scope 不继承调用方 Scoped 实例，亦不抑制 AsyncLocal。管理/存储继续经 Provider 参与工作单元，共享事务仍只允许同物理目标。每次真实路由解析增加一个 scope 与上下文，无新增查询、缓存、重试或异常吞并。
