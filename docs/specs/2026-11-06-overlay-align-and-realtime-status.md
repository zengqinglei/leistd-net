# 浮层对齐回退、实时连接状态呈现与两条上游问题

状态：已完成 · 风险档：中

## 1. 需求

下游反馈 5 项（编号沿用反馈，第 4 项拆成 4a、4b）。基线 develop `794b98c6`。逐项核对后的决定：

| 编号 | 反馈 | 模板现状 | 决定 |
| --- | --- | --- | --- |
| 1 | 仪表盘日期区间日历超出视口 | 仪表盘与操作记录的 `hlm-date-range-picker` 都用默认 `align="center"`。brain `BrnPopover.getAttachPositions()` 只给 `start`/`end` 配了对边回退（源码注释：没有对边候选时 CDK 找不到放得下的位置，只能把浮层压在剩余空间里），`center` 只有上下两个候选，`withPush(false)`，贴边时放不下 | 采纳，模板：使用处指定边对齐，规范写一条通用规则；实测确认现象 |
| 2 | 用户菜单挪到顶栏 | 模板已有两种布局：侧栏布局按 Spartan 官方 nav-user 放侧栏底部（折叠时收成头像）；顶栏布局把头像放在顶栏最右（`app-user-menu variant="topbar"`） | 不采纳改默认：侧栏布局保持官方示例；需要"顶栏头像"的项目已有顶栏布局，或在项目里改用 `variant="topbar"` |
| 3 | 实时连接状态呈现 | 侧栏底部常驻状态卡（徽章 + 短文字 + 提示），连接正常时也占位；顶栏布局与窄屏抽屉收起时看不到 | 采纳，模板：正常时不显示，异常时在内容区顶部显示非阻断提示条，见 §1.2 |
| 4a | `canceledNavigationResolution: 'computed'` 刷新后取消导航跳到别的历史条目 | 模板用默认 `'replace'`，启动失败扣下目标时由 `EntryRouteService` 在 `NavigationCancel` 后 `replaceState` 回目标 | 不采纳：模板不采用 `'computed'`，无此问题；不向 Angular 提 issue（模板不是使用方） |
| 4b | `BrnDialog` 不透传 CDK `closeOnNavigation` | brain 打开 CDK Dialog 时不传该项，取 CDK 默认 `true`：popstate 时直接 dispose 浮层，`stateChanged` 不发 `closed`，只有 `closed` 输出会发；`disableClose: true` 管不到它。下游"不能随导航关闭"的前提很可能不成立；反向风险是所有弹窗、抽屉后退时被直接关掉，绕过 frontend-ui §2.7 的"改动后确认放弃、写请求进行中拒绝退出" | 实测后选第一条：后退即关，写进 frontend-ui §2.7 作为显式选择，见 §1.3、§4 |

### 1.1 浮层对齐（编号 1）

规则（frontend-ui §2.1 一句；frontend-spartan.md 是维护约定，不放用法）：比触发器宽的浮层（日历、日期区间、宽弹层）在使用处指定 `align="start"` 或 `"end"`，不用默认 `center`。依据是 brain 只为 `start`/`end` 提供对边回退：指定任一边后贴边放不下会自动换到对边；`center` 没有回退。按触发器所在一侧选：贴右的用 `end`，其余用 `start`（与 shadcn 日期区间示例的 `align="start"` 一致）。

落点：仪表盘与操作记录的区间选择器都在右侧组，都用 `end`。排查结果：select、combobox 的 helm 默认就是 `start`；模板 4 处 `hlm-popover` 都已写 `start` 或 `end`；dropdown 走 CDK Menu，会被推回视口内、不压窄；只有日期选择器家族默认 `center`。

| 要求 | 验收（Given / When / Then） | 覆盖 |
| --- | --- | --- |
| 贴边不溢出 | Given 视口 1280 与 768，When 打开仪表盘与操作记录的区间日历，Then 面板完整在视口内且不被压窄 | 修复前后浏览器实测（量 `getBoundingClientRect`）；组件 spec 只在 `center` 下能跑红时保留 |

上游：`center` 缺少回退是 brain 的缺口，可以向 Spartan 提 issue（`center` 放不下时回退到 `start`/`end`）。提 issue 属对外动作，经用户确认后再提。

### 1.2 实时连接状态（编号 3）

终局：正常时不显示；异常时在内容区顶部显示 Spartan `hlm-alert` 提示条，两种布局、侧栏折叠与窄屏都看得到。挂载顺序：顶栏 → 导航进度条（零高度叠放）→ 提示条（占布局流，不盖住页面内容）→ 滚动区；工作空间布局里提示条随内容限宽，与页面左右留白对齐，不通栏贴边。frontend-navigation.md 像进度条那样写挂载约定（`IncludeRealTime` 条件块独占一行）。不用 Sonner：状态会持续存在，自动消失的通知不适合，常驻通知又会和业务通知叠在一起。依据：连接正常时常驻状态没有信息量；头像角标在协作产品里普遍表示"本人在线状态"，用来表示连接健康会混淆（下游自己的顾虑成立）；Linear、GitHub、Figma 的做法是正常时隐藏、异常时非阻断提示。

| 状态 | 呈现 |
| --- | --- |
| `idle`、`connected` | 不显示 |
| `reconnecting` | 持续 2 秒以上才显示（SignalR 首次重连立即发起，短暂抖动不打扰）："实时连接中断，正在重连"，默认变体 |
| `disconnected` | 立即显示："实时连接已断开，页面数据可能不是最新"，"重新连接"按钮放在官方 `hlmAlertAction` 槽位（调用现有 `connect()`），`destructive` 变体；原词条"刷新重试"的说法与按钮矛盾，改写 |

无障碍：常驻一个 `role="status"` 的容器，提示条随状态插入其中（随 `@if` 才插入的 live region 多数读屏不播报）；`hlm-alert` 宿主自带 `role="alert"`，用 `[attr.role]="null"` 去掉内层角色。文字完整，不依赖颜色。减少动效：提示条本身没有动效。删除侧栏状态卡及其不再使用的短状态词条。

| 要求 | 验收 | 覆盖 |
| --- | --- | --- |
| 正常不打扰 | Given 已连接，Then 页面无提示条、侧栏无状态卡 | 布局组件 spec |
| 播报容器先在 | Given 状态变化前，Then `role="status"` 容器已经存在，提示条插入其中 | 布局组件 spec |
| 抖动不显示 | Given 重连 1 秒内恢复，Then 不出现提示条；持续 2 秒以上才出现 | spec（假计时器只推进本组件的显示延时） |
| 断开可恢复 | Given 已断开，When 点"重新连接"，Then 调用 `connect()`；连接恢复后提示条消失 | spec |
| 两种布局可见 | Given 侧栏布局、顶栏布局、窄屏，Then 提示条都在内容区顶部 | 生成实例浏览器验收（停后端模拟断线） |

### 1.3 弹窗随后退关闭（编号 4b）

已选第一条（2026-11-06，同日下游另一份 Sheet 统一提案一并考虑后决定）；实测结果写进 §4，与前提不符时回到这里重议。原来的两条路：接受"后退即关、不经确认"并写进 frontend-ui §2.7 作为显式选择（移动端返回手势关弹窗是常见预期）；或另出方案送审。实测必须能区分关闭来源，不用查询参数驱动的投递详情抽屉（后退时路由本身就会关掉它）：
- 不由 URL 驱动的业务弹窗：已改动未保存时后退；写请求进行中后退；
- 记录后退前后 `history.length`、页面路由是否变化、前进能否重开；
- 用 `stateChanged` 是否发出 `closed`、有无退场动画区分 CDK dispose 与组件自身关闭。
- 另记一条下游问到的路由驱动抽屉（投递详情）：后退后 `history.length` 不增加、抽屉关闭，前进能重开。

结论：选第一条。浏览器后退/前进视为离开当前页面，弹窗与抽屉随导航关闭（CDK 默认 `closeOnNavigation`，与 Material 一致），不经 `requestClose()` 确认，进行中的写请求照常完成；模板不提供路由级未保存守卫。frontend-ui §2.7 写明这一选择，并补"本节同样适用于抽屉"。实测见 §4。下游实查：若全局关掉 `closeOnNavigation`，确认对话框、命令面板、窄屏导航抽屉、设置窄屏导航抽屉、服务式选择对话框 5 类弹窗会跨导航残留，所以模板保持后退即关。

## 4. 结果

**浮层对齐**：两处区间选择器改 `align="end"`，frontend-ui §2.1 加一句。
- 仪表盘基线（`center`）在 1280 与 768 宽都复现：浮层被压到视口右缘（宽 202px、186px），248px 的日历伸出视口 45.8px、61.8px，周日列与下月按钮被裁；改 `end` 后与触发器右缘对齐、完整在视口内（390 宽同样）。
- 操作记录的锚点是 288px 宽的输入框，基线居中放得下、不溢出；改 `end` 是按规则统一。
- 组件 spec 保留：仪表盘 spec 在 768 宽下打开日历（此宽度区间选择器在行首），`center` 下浮层被压到 186px（< 248）跑红，`end` 下回退到 `start` 后通过。

**实时连接提示条**：新增 `layout/components/realtime-status`（`IncludeRealTime`），两个布局按顶栏 → 进度条 → 提示条 → 滚动区挂载，工作空间布局限宽到 `max-w-7xl`；删侧栏状态卡与 `label`、`connected`、三个短状态词条，改写 `reconnecting`、`disconnected`，新增 `reconnect`；frontend-navigation.md 补挂载约定。
- 组件 spec 覆盖验收表各行（正常不显示、状态区先在且内层无 `alert` 角色、1999ms 不显示 2000ms 显示、1 秒内恢复不显示、再次重连重新计时、断开立即显示并调用 `connect()`、恢复后消失）；把延时改成 1000ms、恢复内层角色时 3 条用例变红。
- 生成实例（identity-all-features，真实后端）：停后端后侧栏布局、侧栏折叠、390 窄屏、工作空间布局（1440 与 390）都在内容区顶部显示，与页面左右留白对齐，按钮不压文字；连接正常时状态区高 0。重启后端会丢失会话，重新连接得到 401 后仍为断开（预期）；改用浏览器离线模拟断线，恢复网络后点"重新连接"，提示条消失。

**弹窗随后退关闭**（基线代码，identity-all-features 与 webhooks 生成实例）：
- 新建用户弹窗已改动时后退：弹窗在 popstate 之前被移除，没有 `data-state="closed"`（无退场动画），不出放弃确认；路由离开用户页，`history.length` 不变；前进回到用户页、弹窗不重开；无残留浮层、`aria-hidden`、滚动锁。对照：同一弹窗按 Esc 有退场动画、回焦入口，改动后按 Esc 弹出放弃确认。
- 放弃确认已打开时后退：弹窗与确认框一起被移除，无残留。
- 写请求进行中（请求延迟 30 秒）：Esc 被拒绝（对照）；后退时弹窗立即移除、页面离开，请求在服务端照常完成（用户已创建），页面已销毁不再提示；前进后列表里能看到新用户。
- 侧栏抽屉（窄屏，非路由驱动）后退同样立即关闭，焦点回到侧栏开关。
- 投递详情抽屉（查询参数驱动）：后退时抽屉被立即移除（同样无退场动画），`history.length` 不变，焦点落到 `body`；前进重开、焦点在抽屉关闭按钮。用关闭按钮关闭时多推一条历史（`closeDelivery()` 未传 `replaceUrl`），之后后退会重开抽屉。
