# 表格重新加载稳定性与 Vega 弹窗间距

状态：已完成 · 风险档：中

## 1. 需求

平台五张表在重新请求时用单个加载行替换数据，自动布局随内容重算，造成列宽跳动；确认框底栏采用了其他风格的样式，表单弹窗的自定义关闭宿主与正文留白又额外占据间距。用户于 2026-11-01 确认统一修复模板及其规范，一个 PR 交付，不改业务项目、不发布正式版。

| Given / When | Then | 验收 |
| --- | --- | --- |
| 五张表无数据，首次加载 | 按可见列显示五行骨架，有加载读屏文字 | TableLoading 单测、浏览器 |
| 已有数据，刷新、保存、翻页、筛选 | 请求期间保留行与列宽、高度；行区淡化且不可交互；容器 aria-busy；刷新按钮转圈并禁用 | TableLoading 单测、五页逐帧实测 |
| 请求失败或成功空数据 | 保留已有失败提示、重试及空态；重新加载失败保留原数据 | 现有页面测试、浏览器 |
| Vega 表单弹窗及服务动态确认框 | 关闭按钮不占流；内边距与正文到页脚的视觉间距遵循 Vega；短横屏正文滚动且按钮可达 | ConfirmService、DialogClose 测试，三种视口人工验收 |
| 正文首尾控件聚焦 | 焦点环在全部裁剪祖先的可见矩形交集中完整显示 | 浏览器几何测量 |

保留内容自动布局与 appTableFit，不冻结真实新数据返回后的列宽。所有模板条件保持独占一行；加载文案复用根 `app.startup.loading`，非本地化场景提供相同英文。

## 2. 方案

共用 TableLoading 组件管理首次加载与重新加载状态、读屏状态、容器 aria-busy 和逐列骨架模板；配套 TableLoadingBody 指令在数据行区设置 inert 与淡化，状态提示留在其外。五张表继续使用现有行模板和手动分页模型，五个刷新按钮组合官方 Spinner。

确认框使用官方 DialogFooter；标题区因命名 group 与 Brain 根不同，在组件内等价实现 Vega 默认尺寸布局，保留原有 alertdialog 角色和 aria 关联。DialogClose 宿主使用 display: contents，按钮沿用 Helm 原定位。正文纵向 padding 与负 margin 等量补偿，表单 gap 和弹窗 padding 同源。修改前后均核对表单、动态确认框与 sheet。

## 3. 计划

1. 增加共用加载实现与回归测试，接入五张表、五个刷新入口；扫描其他内容替换区域，记录处理依据。
2. 修复确认框和公共弹窗间距，补结构、ARIA 与关闭宿主测试；在 390×667、1440×900、667×390 验证几何和焦点可见性。
3. 同步 frontend-ui、frontend-spartan 与文档索引，读取成本上限保持原值；检查项目 Skill 示例是否需要修改。
4. 生成 identity-all-features、identity、standalone、resource 及 control；完成指定前端测试、lint、生产构建与静态闸门。推送 PR 后等待最终 head 的 Claude 审查和全绿 CI，再以匹配 head 合并。

## 4. 结果

五张表接入共用加载状态，重新加载保留原行，首次显示与可见列数一致的五行骨架；开放应用与操作记录骨架随窄屏正文布局调整行高。保留内容自动布局与原有错误处理。

确认框对齐 Vega 并接入独立正文滚动；自定义关闭按钮移出布局流，公共弹窗间距与焦点环留白同源。四类表单在三种视口均达到 24px 内距和正文间距，关闭按钮与 Helm 位置、尺寸一致；五表三视口共 72 次加载验证未出现加载期列宽变化。

前端两场景完成全量测试、lint 与生产构建；Standalone 一项 OTP 浏览器输入超时经该文件定向重验通过。最后的响应式骨架调整补做受影响组件测试与两场景 lint、构建。五场景生成、control、静态检查、Spartan 定制登记与读取成本检查通过；本 PR 的 CI 与最终 head 代码审查仍是合并前置条件。

现行规则已同步到 `frontend-ui.md`、`frontend-spartan.md` 与项目文档索引。项目 Skill 中无须同步的整块加载替换示例，未改 Skill；没有修改框架或发布输入，不触发框架 beta，不发布正式版。
