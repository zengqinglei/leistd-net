# 表格重新加载稳定性与 Vega 弹窗间距

状态：已完成 · 风险档：中

## 1. 需求

平台五张表在重新请求时用单个加载行替换数据，自动布局随内容重算，造成列宽跳动；确认框底栏采用了其他风格的样式，表单弹窗的自定义关闭宿主与正文留白又额外占据间距。用户于 2026-11-01 确认统一修复模板及其规范，一个 PR 交付，不改业务项目、不发布正式版。

| Given / When | Then | 验收 |
| --- | --- | --- |
| 五张表无数据，首次加载 | 按可见列显示五行骨架，有加载读屏文字 | TableLoading 单测、浏览器 |
| 已有数据，刷新、保存、翻页、筛选 | 请求期间保留行与列宽、高度；行区淡化且保留交互与焦点；表格区域 aria-busy，读屏状态在外；刷新按钮转圈且可再次触发 | TableLoading 单测、五页逐帧实测 |
| 请求失败或成功空数据 | 保留已有失败提示、重试及空态；重新加载失败保留原数据 | 现有页面测试、浏览器 |
| Vega 表单弹窗及服务动态确认框 | 关闭按钮不占流；内边距与正文到页脚的视觉间距遵循 Vega；短横屏正文滚动且按钮可达 | ConfirmService、DialogClose 测试，三种视口人工验收 |
| 正文首尾控件聚焦 | 焦点环在全部裁剪祖先的可见矩形交集中完整显示 | 浏览器几何测量 |

保留内容自动布局与 appTableFit，不冻结真实新数据返回后的列宽。所有模板条件保持独占一行；加载文案复用根 `app.startup.loading`，非本地化场景提供相同英文。

## 2. 方案

共用 TableLoading 组件管理首次加载与重新加载状态、读屏状态和逐列骨架模板；配套 TableLoadingBody 指令只淡化数据行，保留键盘焦点与交互；表格区域标忙，状态提示在其外。五张表继续使用现有行模板和手动分页模型，五个刷新按钮组合官方 Spinner。

确认框使用官方 DialogFooter；标题区因命名 group 与 Brain 根不同，在组件内等价实现 Vega 默认尺寸布局，保留原有 alertdialog 角色和 aria 关联。DialogClose 宿主使用 display: contents，按钮沿用 Helm 原定位。正文纵向 padding 与负 margin 等量补偿，表单 gap 和弹窗 padding 同源。修改前后均核对表单、动态确认框与 sheet。

## 3. 计划

1. 增加共用加载实现与回归测试，接入五张表、五个刷新入口；扫描其他内容替换区域，记录处理依据。
2. 修复确认框和公共弹窗间距，补结构、ARIA 与关闭宿主测试；在 390×667、1440×900、667×390 验证几何和焦点可见性。
3. 按代码审查修正可访问性、确认框 512px 宽度与页头让位；空态、表头、验证码占位、链接按钮和快捷入口复用官方组件；重置密码提示复用 Alert，权限摘要复用 Badge，通知条目保持非嵌套交互。
4. 同步 frontend-ui、frontend-spartan、frontend-lists 与文档索引，读取成本上限保持原值；检查项目 Skill 示例是否需要修改。
5. 生成 identity-all-features、identity、standalone、resource 及 control；完成指定前端测试、lint、生产构建与静态闸门。推送 PR 后等待最终 head 的 Claude 审查和全绿 CI，再以匹配 head 合并。

## 4. 结果

五张表接入共用加载状态，重新加载保留原行、交互和焦点，首次显示与可见列数一致的五行骨架；开放应用与操作记录骨架随窄屏正文布局调整行高，触屏骨架也覆盖 44px 按钮的实际行高。读屏状态位于 busy 表格区域之外，刷新按钮转圈且可重复触发。保留内容自动布局与原有错误处理。

确认框使用经本地服务 API 查证的 contentClass 设置 512px 最大宽度，Vega 图标为 32px；正文独立滚动，自定义关闭按钮移出布局流，公共弹窗间距与焦点环留白同源。四类表单在三种视口均达到 24px 内距和正文间距，关闭按钮与 Helm 位置、尺寸一致。触屏 Dialog 页头让位 36px，Sheet 为 60px，长标题不与关闭按钮重叠；五表三视口首轮共 72 次加载与修订后两表抽样均未出现加载期列宽变化。

通过锁定 1.9.0 的 CLI 引入未定制的 Empty，替换表格、设置、通知和仪表盘空态及失败态，保留重试选择器与 alert 语义；所需依赖已安装，两个 package 变体及锁文件无须变动。排序表头复用 ghost/sm 按钮并抵消起始内边距与透明边框，触屏选择列邻接处同步补偿，保持文字对齐和独立命中区。验证码使用 Skeleton，重新发送与全部已读使用 link 按钮；仪表盘快捷入口、工作台搜索使用 Button。通知条目的整行覆盖按钮及独立操作需要保持非嵌套结构，继续沿用既有实现。

重置密码使用默认 Alert 加警示图标表达提示，无须新增 warning 变体或扩大 Helm 定制；权限摘要使用 secondary Badge，保留截断、计数、弹出明细及测试选择器。URI 代码片段和规范已登记的 stat-panel 托盘卡保持原设计。

最终前端两场景全量测试通过：identity-all-features 150 文件/1714 项、standalone 126 文件/1358 项；两场景 lint、生产构建通过。五场景 GenerateOnly（含 LocalIdentity=false、Localization=true）、check-i18n、control、50 道静态闸门、Spartan 定制登记与读取成本检查通过；ui-change 为 52932/52932，上限未变。本 PR 的最终 head 代码审查及 CI 全绿仍是合并前置条件。

现行规则已同步到 frontend-ui、frontend-spartan、frontend-lists 与项目文档索引。项目 Skill 中无须同步的整块加载替换示例，未改 Skill；没有修改框架或发布输入，不触发框架 beta，不发布正式版。
